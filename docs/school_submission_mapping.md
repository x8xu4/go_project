## Recommended source submission contents

Include production Flutter/Python/native source, tests, `packaging/macos/` scripts/spec/dependency manifests, `analysis.cfg`, required production corpus, and project/release documentation. The large model should be delivered according to school upload limits or as a separately checksummed runtime asset.

Exclude generated Flutter/PyInstaller builds, portable staging trees, caches, logs, temporary SGFs, local virtual environments, and duplicate release extraction directories. Keep benchmark/research artifacts only when they are needed to substantiate the methodology; they should be clearly separated from production source.
